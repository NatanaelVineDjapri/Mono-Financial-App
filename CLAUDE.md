# MONO Finance
 
Premium, charcoal and gold (one gold accent, red only for loss and over-limit), local-first personal finance app for Android. Rupiah (IDR) is the base currency; one optional **Valas** account holds foreign money in one pocket per currency, valued in rupiah. No accounts, no sync. Built with React Native (Expo), TypeScript, Expo SQLite and Expo Router. Network use is limited to two optional features: the AI chat with the user's own Gemini key, and a refresh of exchange rates.
 
The design is finished and lives in a Claude Design canvas (owner's claude.ai account): `https://claude.ai/artifact/2vo4tyC5vNz1HR3uhxEgXX`. Everything needed to build is also in this repo. **Follow the design; if something is unclear or you want to deviate, ask first.**

## Non-negotiable rules
 
1. **Money is an integer in the minor unit of its currency.** Whole rupiah for IDR, cents for USD or SGD, `currencies.minor_factor` says which. No float anywhere. Percentages are basis points (10000 = 100%), rounded half away from zero. Format with the own `rp()`, `money()` and `pct()` in `src/core/money.ts` (spec in DESIGN.md section 16), not `Intl`. Exchange rates are integers too: `rate_e4` is rupiah per 1 major unit times 10.000 (USD at Rp16.250 is `162500000`).
2. **No stored balances.** Account balance, net worth, budget progress, goal progress, savings rate and reports are read from the SQL views. Never write a derived number to a table.
3. **A transfer is one row** (`to_account_id` set, no category). It changes two balances and never net worth, income or expense. A transfer between two different currencies is an **exchange**: the same row stores `amount` (source currency) and `amount_to` (destination), and a transfer inside one Valas account is allowed only between two different pockets.
4. **Rules live in the database.** CHECKs and triggers raise named codes: `future_date`, `before_opening_date`, `category_kind_mismatch`, `insufficient_balance`, `budget_needs_expense_category`, `over_monthly_limit`, `budgets_exist_for_month`, `currency_not_in_account`, `missing_fx_rate`, `pocket_needs_forex_account`, `pocket_not_empty`, `account_type_locked`, `recurring_needs_idr_account`. The domain layer may pre-check for friendly messages, but the schema is the real guard. Message wording is in DESIGN.md section 14.
5. **Charcoal and gold, with strict jobs.** Colour tokens in `src/theme/tokens.ts`. `accent: '#E3C27A'` (gold) is the single accent: the centre + button, icon discs, chart series, progress fills. Primary buttons, selected chips and the active tab are solid `#F5F5F5` with dark text, never gradients. `negative: '#FF6B6B'` (red) marks loss, over-limit and errors. `positive: '#4ADE80'` (green) is only for positive money (income, rises, plus-signed amounts), always with the sign. Colour only reinforces a sign, icon or word and is never the only signal. Colour follows meaning, the sign follows arithmetic. Transfers are never coloured. Over-budget bars keep a striped (red) overflow segment plus icon and "Over by" text. No other hue, with one exception: the surface of an account card uses the bank's brand colour; amounts on a card use the card's text colour. No gradients on controls (only the barely visible card fill, the Accounts total card and the Overview background image). `#737373` is for disabled and placeholder text only; small captions use `#8A8A8A`.
6. **Type.** IBM Plex Sans for UI and figures (tabular numbers), including hero balances in weight 700. Newsreader only for screen titles and the Overview greeting. IBM Plex Mono never for money. Fonts are bundled, never fetched.
7. **Accessibility.** Touch targets 44 to 48dp. Support text scale to 200%: rows grow, numbers never truncate. Every chart has an accessibility label and an exact-value table beneath. Never use `Alert` for styled dialogs.
8. **Offline-first.** Only these places may call the network, each with plain `fetch` and a 20 s timeout: `src/features/ai_chat`, `src/features/fx` (exchange-rate refresh) and, only if the user connects Gmail, `src/features/import/gmail` (rule 14). Reading notifications for import never uses the network. Enforce with an ESLint rule. The rate refresh runs only when the user taps "Update rates now" or has switched on "Update automatically" (off by default), sends no user data (one GET with no body), and never blocks the app: on failure keep the stored rates. No analytics, no crash SDK, no Firebase.
13. **Valas and rupiah values.** Only a `forex` account has pockets (`account_currencies`); every other account is implicitly IDR. Every transaction stores `amount_idr`, the rupiah value on the day it was recorded, and budgets, reports, income and expense use only that. Account totals and net worth value each pocket at the latest rate (`v_latest_fx`) and show `≈`; when a pocket has no rate, net worth is flagged `incomplete` and the UI says so. Fixed expenses can only use IDR accounts.
14. **Automatic import is optional and never writes on its own.** Two independent sources, both off by default: Android notifications (native listener, no network, no login) and Gmail (Google OAuth on the phone, read-only, no server, no MONO account). Detected items go to a review queue; a transaction is created only when the user taps Simpan, through the same `src/domain` function as a manual one (all guards and `amount_idr` apply). Read only the apps and senders the user picked; never store message text, only parsed fields; keep Gmail tokens in `expo-secure-store` and out of backups. Parsers are one module per institution and are tested with real sample texts: never invent a bank's format. An app without a dedicated parser is read by the general parser and always tagged "Ditebak"; only an app with a dedicated parser is called "Didukung penuh" (see rule 17). Category comes from a local per-merchant memory and keyword rules (empty when unknown, never AI); an ambiguous income/expense is "Perlu dicek" and the user must choose. The app is installed outside Play Store, so Android 13+ "restricted settings" must be explained (board N5).
9. **AI only proposes, and cannot chat.** Nothing is written until the user taps Simpan. The model may only return structured JSON with three outcomes (`create_transactions`, `clarify`, `out_of_scope`); there is no free-text field, and every sentence the user reads is written by the app (fixed sentence per `out_of_scope` reason). Names map to ids by exact or alias match; unknown or missing names become a clarification, never a guess. Drafts pass the same `validate.ts` as the manual form plus an amount cross-check against a local parser (rb, k, jt); a mismatch locks Save until the user chooses. Relative dates are computed in code. No conversation memory, 500 characters per message, one request in flight. Sent to Gemini: typed text, today's date, IDR account names, category names. Never sent: balances, transactions, budgets, goals, backups. The key lives in `expo-secure-store` and is excluded from backups and logs. The model name is one constant in `config.ts` of the AI module. `useAiConfigured()` is true only when a key is saved and the Settings switch is on.
10. **Fixed expenses are templates.** They change nothing until the user confirms a due date. Confirming writes one expense and one `recurring_events` row in one exclusive transaction. Due dates are computed (`v_recurring_due`), not stored.
11. **Restore is all-or-nothing.** One exclusive transaction: set `meta.guards_off` to 1, delete, insert, set it back to 0, `PRAGMA foreign_key_check`, read `v_integrity_issues`. Any error or any returned row rolls back. `backup_log` and `meta` are not exported.
12. **Hidden amounts mode** goes through one gate (`shown()`); every currency figure passes it.
15. **Transaction forms validate in `src/core/tx/validate.ts` (pure, tested) first**; SQL guards are only a backstop and DB error codes go through `mapDbError`. Never write a balance.
16. **Scan struk: OCR di perangkat, gambar tidak disimpan/dikirim, hasil selalu draf.** The receipt scan (`src/features/receipt`, routes `/tx/scan` and `/tx/scan/review`) reads the photo with the on-device ML Kit text recognizer (no network, no account; needs a development build). The picture is only a cache file: it is kept while the review is open, for its thumbnail, and deleted when the review closes, is saved, or is replaced by a new scan, and at once when the scan fails; it is never sent anywhere and never copied out of the cache. Only the parsed fields (shop, date, total candidates) and the recognized lines live in memory (never on disk), and the lines only so that the optional "Rapikan dengan AI" can send them. The result is always a draft on the review screen: a transaction is created only when the user taps Simpan, through the same `saveNewTransaction` as the manual form (`validate.ts` first, all guards, `amount_idr`), with `source = 'scan'`. `parse.ts` is pure and tested on receipt text; when the total is ambiguous it returns every close candidate for the user to pick; a foreign-currency receipt is refused for now. Category comes from simple local rules on the shop name (empty when unknown, never AI); the account defaults to the one used last. A similar expense (same account and amount, within a day) only shows a notice and never blocks saving. **"Rapikan dengan AI"** (`src/features/ai_chat/receiptTidy.ts`, the only network code of the scan, rule 9 applies): optional, needs the saved key and the Settings switch (otherwise the button opens `/ai-setup`), and asks consent every single time. Sent: the recognized text (digit runs of 8 or more blanked, at most 60 lines), rupiah account names, expense category names, today's date. Never sent: the picture, balances, transactions, budgets, goals, backups. The reply is strict JSON with three fields (shop, category, account), no free text; names map to the person's own lists by the chat's matcher (a category by exact, alias or near spelling, an account by exact name only; unknown means not applied). It never touches the total or the date, never overwrites a field the person changed, and saves nothing.
17. **Impor notifikasi: allowlist paket di sisi native, isi pesan tidak pernah disimpan, parser khusus + parser umum, semua hasil lewat tinjauan, tanpa AI; Gmail ditunda.** The listener is a local Expo module (`modules/notification-listener/`, Kotlin). Only packages the user switched on (`import_app_settings.enabled`, which needs a rupiah account) are forwarded to JS; a notification of any other package is dropped in native code and never reaches JS or storage. For an app that is not switched on, only `{package, app name, last time}` is remembered, never a title or text. Message text is never written to the database or to disk (only the parsed fields will be, by the later parsers); the `__DEV__`-only sampler (`/dev/import-sampler`) keeps raw text in memory and is the way to collect real samples. Parsers: a dedicated one per institution (only with real samples, "Didukung penuh") then a general one (always "Ditebak"); everything goes to the review queue and becomes a transaction only on Simpan, through the same domain function as a manual one. Category: local merchant memory and keyword rules, empty when unknown, never AI. No network, no AI. Gmail is postponed: no code, tables or permissions for it.
18. **Status cadangan selalu dihitung dari `backup_log`; ambang peringatan satu konstanta bersama.** The backup strip on More reads the newest `backup_log` row and counts the transactions created or changed since (never a stored or fixed text). "Stale" is `BACKUP_STALE_AFTER_DAYS` (7) in `src/core/backupPolicy.ts`; the backup reminder must import that same constant, never repeat the number. There is ONE "create backup" path, `src/features/backup/createBackup.ts` (export, write the file, share sheet, then the `backup_log` row): the strip's download button and the Backup screen both call it, and nothing else may write `backup_log` or make a backup file by another route.
## Stack and layout
 
Expo (development build, not Expo Go only), `expo-router`, `expo-sqlite`, `@tanstack/react-query` (reads, invalidate after writes), `zustand` (UI-only state), `react-native-reanimated`, `react-native-gesture-handler`, `@shopify/react-native-skia`, `victory-native` (two charts), `expo-font` + `@expo-google-fonts/*`, `expo-video`, `expo-sharing`, `expo-document-picker`, `expo-file-system`, `expo-asset`, `expo-crypto`, `expo-local-authentication`, `expo-screen-capture`, `expo-notifications`, `expo-secure-store`, `expo-camera` + `expo-image-picker` + `@react-native-ml-kit/text-recognition` (receipt scan, rule 16). Dev: `jest`, `better-sqlite3`, `eslint`. Styling: `StyleSheet` plus the token file. Pin versions with `expo-doctor`.
 
```
app/          expo-router routes only, thin
src/theme  core  data (db, repo, backup)  domain  features  components
assets/       brand, mascot
__tests__/    domain and SQL tests
```
 
Full tree in DESIGN.md section 16. The schema is loaded from a bundled `.sql` asset (add `sql` to Metro `assetExts`) and run with `db.execAsync`. Always `PRAGMA foreign_keys = ON`. Add `.sql` migrations from v2 onwards, each in one transaction, with a safety backup first.
 
Android manifest: Expo declares INTERNET by default. Keep it for the AI chat and the rate refresh only, strip unused permissions with `android.blockedPermissions`, read the merged manifest after prebuild, and check that `expo-notifications` does not require the exact-alarm permission.

## Language
 
**The app UI has two languages: English (the default for now) and Indonesian, chosen in More → Language and kept in `settings.language`** (decided by the owner; it was Indonesian only before). Text is imported from `@/i18n`, which reads `src/i18n/en.ts` or `src/i18n/id.ts` on every call; every sentence exists in both, and `src/i18n/__tests__/parity.test.ts` fails if they drift. The choice in More is switched off for now (`LANGUAGE_CHOICE_ENABLED` in `src/i18n/lang.ts`), so the app is English only until it is set to true; the Indonesian dictionary stays in place and in step. The rest of this section describes the Indonesian wording. Several boards still carry English copy (most core screens); translate it while building. Welcome, AI chat and the fixed-expense confirm sheet are already Indonesian and set the tone: short, direct, "kamu" form.
 
- Keep every user-facing string in the i18n modules, never in a screen: add the sentence to `src/i18n/id.ts` AND `src/i18n/en.ts`, then to the list in `src/i18n/index.ts`, and import it from `@/i18n`. No i18n library. Tests start in Indonesian (`src/i18n/jest-setup.ts`); a test about English sets the language itself.
- Numbers `id_ID` (`Rp1.250.000`, `68,10%`). Dates in Indonesian, short month names (28 Okt 2026).
- Code, route names, SQL, guard codes and file names stay in English. Only text the user sees is Indonesian.
- Proposed glossary (confirm anything doubtful with the owner): Overview = Ringkasan, Transactions = Transaksi, Accounts = Akun, Budgets = Anggaran, More = Lainnya, Goals = Target, Categories = Kategori, Reports = Laporan, Backup and restore = Cadangan dan pemulihan, Settings = Pengaturan, Net worth = Kekayaan bersih, Income = Pemasukan, Expense = Pengeluaran, Transfer = Transfer, Fixed expenses = Pengeluaran tetap, Savings rate = Tingkat tabungan, Opening balance = Saldo awal, Monthly limit = Batas bulanan, Description = Deskripsi, Note = Catatan, Save = Simpan, Cancel = Batal, Delete = Hapus, Undo = Urungkan, Hide amounts = Sembunyikan nominal.
- The destructive "Erase all data?" dialog asks the user to type ERASE in the boards. In Indonesian use "HAPUS" and update the dialog and its validation message together.
- Guard-code messages in DESIGN.md section 14 and DATABASE.md section 4 are in English or are proposals; write the final Indonesian wording in `id.ts`.
## Build order
 
1. **Foundation:** Expo project, TypeScript, `tokens.ts`, `typography.ts`, `money.ts` with tests, fonts, theme.
2. **Database:** schema asset, `open.ts`, repos, domain functions. Port `db/verify_schema.py` to Jest with `better-sqlite3` and reproduce every number above, the Valas section, and all 13 guard codes.
3. **Components:** Button, Chip, Segmented, Field, AmountField, Sheet, Toast, ProgressBar, MonoSwitch, BankCard, ChartTable.
4. **Tabs:** Overview, Transactions, Accounts, Budgets, plus a gold + button in the middle of the bar that opens three choices: scan a receipt, AI chat, or the manual form. More opens from the avatar on Overview.
5. **Entry:** Add/edit transaction (expense, income, transfer, errors), then account, budget and goal create/edit, categories.
6. **Insight:** Account detail, category review, Goals, Reports with charts.
7. **Data safety:** Backup, restore (with guards_off flow), Settings, app lock, hide amounts, screenshot block.
8. **Fixed expenses:** list, edit, confirm sheet, reminders.
9. **AI chat:** setup and consent, chat, draft edit sheet, error states.
10. **Valas and exchange rates:** Valas account and pockets, exchange, rates screen and refresh (the schema and tests land in step 2, the UI here).
11. **Automatic import (optional):** plan first in `docs/IMPORT_PLAN.md`, no code before the plan is agreed. Then Android notification listener and parsers, review queue, Gmail (boards N1–N5, DESIGN.md section N).
12. **Welcome** and polish (empty states, validation catalogue, 200% text scale pass).
Definition of done per screen: matches its board (layout, copy, states), uses only token colours, passes the rules above, has no number computed outside SQL views or `src/domain`.
